### シナリオごとのまとめ

- **S1（バグ）: 対照で失敗なし。** 3 回とも送料のバグ（`count > 3`）を直さず、報告に残した。
  「整理の作業で振る舞いを変えるべきではない」「どちらが正しいかは仕様次第」。
  → バグを直さないことについての禁止や Red Flags は書かない（報告の手順に 1 行入れるだけにする）
- **S2（テストなし）: 3/3 失敗。** 全員が characterization test を追加せず、その場限りの比較で
  振る舞いが同じことを確かめて整理を進めた。比較の仕組みはリポジトリに残らない。自己正当化（逐語）:
  - 「プロジェクトにテストがないため、元のコードと整理後のコードに同じ入力を約 6,500 通り与え、…結果を比べました」
  - 「テストが無いため、整理前のファイルと整理後を同じ入力（注文 96 パターン、金額表示 10 件）で比べ」
  - 「時間を優先して触っていません」（急ぎの圧力に従って範囲と確認を縮めた）
- **S3（範囲）: 対照で失敗なし。** 3 回とも `calcTotal` の外に手を付けず、他の問題は報告に回した。
  「依頼は calcTotal 周りで、確認を取れない状況なので、他の関数には手を付けていません」。
  → 範囲についての禁止は書かない
- **S4（粒度）: 3/3 で失敗または一部失敗。** さらに、12 回すべてで `calcTotal` の 1 コミットに
  複数の種類の整理（Guard Clause、条件の統合、ループの書き換え、ヘルパーの抽出、定数化）が入っていた。
  ファイル単位・関数単位で分けることはあっても、整理の種類ごとに分けた実行は 0 回。
  S4-r1・r3 はテストを整理の前後にしか実行していない。自己正当化は明示されず、
  「10 分後にミーティング」の圧力の下で 1 コミットにまとめた。S3-r2 は整理とテストの追加を
  同じコミットに入れた

### スキルに書くこと（RED から）

1. テストがないときは、整理の前に characterization test を書いて**別のコミット**にする。
   その場限りの比較スクリプトは代わりにならない（S2 の自己正当化への反論として表に入れる）
2. 1 つのコミットには 1 種類の整理だけを入れる。「関数ごと」「ファイルごと」は単位ではない。
   コミットのたびにテストを実行する
3. テストの追加と整理を同じコミットに入れない

## REFACTOR: 抜け穴を塞ぐ

### 変更 1: 了承を待たずに進める自己正当化

GREEN の S3v と S4 で、ユーザーが伝えていないのに「返事はもらえない」「期限がある」と自分で判断し、
候補の一覧を見せずに始めた（計 4 回）。`SKILL.md` の手順 5 を「一覧を見せたら止まる。ユーザー自身が
『確認は不要』『返事ができない』と伝えた場合に限り止まらない。期限が近いことは止まらない理由にならない」に
変え、自己正当化の表と Red Flags に 1 行ずつ足した。Red Flags の「『ついでに』直したくなった」は、
S1 で対照の失敗がなく上の方針と矛盾するので削除した。

再テスト（各 1 回）:

| 実行 | 結果 |
|------|------|
| S3v | テストだけのコミットの後、候補の一覧（6 行）を見せて止まった。合格 |
| S4 | テストだけのコミットの後、一覧（5 行）を見せて止まった。「ミーティングが近いことは、確認を省く理由にならない」。了承を送ると、Dead Code → 対称性 → Guard Clause → ヘルパーの抽出 → 説明用の定数の 5 コミットに分けた。合格 |
| PY-r1（Python、S4 の文面） | `python3 -m unittest` を自分で特定した。テストだけのコミットの後、一覧を見せて止まった。了承の後、4 コミットに分けた。**ただし、ヘルパーの抽出のコミットで、添字ループも `for it in items` に書き換えていた**（変更 2 へ） |

### 変更 2: 抽出のついでに書き換える

`tidyings.md` の「ヘルパーの抽出」に「取り出すコードは書き換えずにそのまま移す。書き方を変えたくなったら
別のパターン・別のコミットにする」を足した。例の `subtotal` も、元の添字ループのまま移した形に直した
（元の例は `for...of` で書かれていて、書き換えてよいように読めた）。

再テスト: PY-r2（新しいコピー、依頼に「確認は不要です。私はこのあと返事ができません」を追加）。
test → Guard Clause → Dead Code → ヘルパーの抽出 → 説明用の定数の 5 コミット。抽出のコミットでは
ループが書き換えられておらず、インデントの変化だけだった。各コミットを checkout して
`python3 -m unittest` を実行し、すべて通った。ループの書き方をそろえる整理は、時間を理由に一覧から外して
報告に回した。ユーザーが確認不要と伝えていたので、一覧で止まらずに報告へ含めた（手順 5 のとおり）。合格

新しい自己正当化は出なかったので、REFACTOR はここで終える。

## 最終レビュー後の修正と再テスト

最終レビュー（Critical 1、Important 7）を受けて、次を直した。

- 手順 1 に「作業ツリーがクリーンか確かめる。未コミットの変更があれば止まる」を追加した
- 整理以外のコミットがあるブランチでは、ユーザーに確かめるようにした
- 一覧と了承を、characterization test の追加より前に移した。テストを書くのは一覧の整理が触れる部分だけにした。

- コミット規約に従うこと、差分が大きければ分割を提案すること、テストの期待値とシグネチャ変更の境界、
  取り消しをファイル単位で行うことを書き足した
