# commit スキルのタイトル文字数制限の緩和 設計（短）

## 意図

- タイトル 50 文字の上限は、ラベルを重ねる接頭辞や説明的なタイトルでは窮屈。常識の範囲で
  超えられるようにしたい（ユーザーの要望）。
- 一方で、普段は短く書く習慣は保ち、長すぎる subject だけを止めたい。

## 検討した方式

- A. 50 文字を目安（注意だけ）にし、機械チェックの上限を別に設ける。**ユーザーが選択。**
- B. 上限の数を上げるだけ。上限の手前まで長さを気にしなくなるため不採用。
- C. 機械チェックの上限をなくす。極端に長い subject も通るため不採用。

## 決まった設計

- 目安: タイトル（接頭辞と末尾の Issue 番号を除く）50 文字（コードポイント数、今と同じ数え方）。
  超えたら注意を出すが合格（終了コード 0）。
- 上限: subject の 1 行全体（接頭辞と Issue 番号を含む）72 文字（コードポイント数）。超えたら
  不合格。
  - 根拠: GitHub は 1 行目が 72 文字を超えると PR タイトルやコミット一覧で省略表示する
    （公式文書ではなくコミュニティの報告。日本語でも文字数で数えるかは未確認）。
- 拡張の有無にかかわらず同じ（拡張の接頭辞も上限の 72 文字に含む）。

## ビルダーに任せること（設計者の判断として計画で決める）

- 注意の出し方（戻り値の形、CLI の出力先と文言）。
- 手順書での注意の扱い（短くできるなら短くする。意味を損なうなら残してよい）。
