# 整理パターンのカタログ

tidying スキルの一部です。整理の候補を選ぶときに読みます。パターンは Kent Beck『Tidy First?』で
扱われているものを、要点だけ書き直したものです。

**どのパターンも振る舞いを変えません。** 振る舞いが変わるなら、それは整理ではありません。
**1 つのコミットには、この表の 1 つのパターンだけを入れます。** 同じパターンを同じファイルの
複数の箇所に適用するときは、1 つのコミットにします（候補の一覧の 1 行 = パターン × ファイル）。
その整理に伴って必要になる追従（呼び出し元の更新、テストの呼び出し方の変更、ファイルをまたぐ
移動の移動先など）は、別のファイルでも同じコミットに含めます。

## 一覧

| パターン | ひとことで |
|----------|------------|
| Guard Clause | 前提条件を先頭で返し、入れ子を浅くする |
| Guard Clause（条件の統合） | 入れ子の `if` を 1 つの条件にまとめ、冗長な条件を消す |
| Dead Code の削除 | 呼ばれていないコードを消す |
| 対称性をそろえる | 同じことを同じ書き方にそろえる |
| 新しいインターフェース、古い実装 | 呼びたい形の関数を作り、中で古い実装を呼ぶ |
| 読む順に並べる | 読み手が最初に知りたいものを上に置く |
| 凝集の順に並べる | 一緒に変わるものを隣に置く |
| 宣言と初期化を近づける | 変数を使う直前で、値と一緒に宣言する |
| 説明用の変数・定数 | 式やリテラルに名前を付ける |
| 明示的な引数 | 暗黙に読んでいる値を引数で渡す |
| 文のまとまり | 意味のまとまりごとに空行で区切る |
| ヘルパーの抽出 | 目的のはっきりしたまとまりを関数にする |
| いったん 1 か所にまとめる | 細かく散らばったコードを一度まとめて読む |
| 説明用のコメント | コードから読み取れない理由を書き足す |
| 冗長なコメントの削除 | コードと同じことを言っているコメントを消す |

## Guard Clause

**使う場面:** 関数の本体全体や大部分が `if` で包まれていて、入れ子が深いとき。

**手順:** 条件を反転し、満たさない場合に先頭で `return` します。元の `if` が包んでいた範囲を
確かめ、**包まれていなかった処理が条件を満たさないときにどう動いていたか**を必ず保ちます。

```typescript
// 前
function calcTotal(order: Order): number {
  let total = 0;
  if (order.items.length > 0) {
    total = subtotal(order);
    if (order.coupon === "SAVE500") total -= 500;
  }
  return Math.round(total * 1.1);
}

// 後: 外側の if を消すだけだと、空の注文にクーポンが付いたとき -550 を返すようになる。
// 元は 0 を返していたので、その値を先頭で返す
function calcTotal(order: Order): number {
  if (order.items.length === 0) return 0;
  let total = 0;
  total = subtotal(order);
  if (order.coupon === "SAVE500") total -= 500;
  return Math.round(total * 1.1);
}
```

このパターンは、先頭で返すガードを置くことだけです。入れ子になった `if (a) { if (b) { ... } }` を `if (a && b)` にまとめたり、冗長な条件を消したりするのは、一覧の別の行（「Guard Clause（条件の統合）」と書きます）にして、別のコミットにします。内側の `if` に `else` がある場合、まとめると振る舞いが変わるので、まとめてはいけません。

## Dead Code の削除

**使う場面:** どこからも呼ばれていない関数、到達しない分岐、使われていない変数があるとき。

**手順:** 呼び出し元がないことを検索で確かめます（export されているなら、パッケージの外からの
利用も考えます）。文字列で組み立てた名前での呼び出し、リフレクション、フレームワークが名前で
呼ぶフック（ライフサイクルメソッドなど）は検索で見つからないので、その可能性も確かめます。
消します。「いつか使うかもしれない」は残す理由になりません。必要になればバージョン管理から
戻せます。

## 対称性をそろえる

**使う場面:** 同じことをする処理が、場所によって違う書き方になっている（`var` と `const`、
`for` と `for...of`、早期 return と if-else など）とき。

**手順:** どちらかの書き方に決め、片方をもう片方に合わせます。違いが本当に意味を持っている
（片方だけ例外を扱っている、など）場合は、そろえずに説明用のコメントを検討します。
`var` を `let` / `const` にするときは、その変数を宣言したブロック（ループや if）の外や、宣言より前で
読んでいないこと、関数（クロージャ）が捕まえていないことを確かめます。`var` は関数全体で 1 つの
変数になり、宣言より前でも読めるので、どれかに当たると結果が変わります。その場合は `var` のまま
残します。
`const` にするのは、再代入していない変数だけです。

```typescript
// 前: 同じファイルの他の関数は const / let を使っている
var s = String(n);
for (var i = 0; i < s.length; i++) { /* ... */ }

// 後
const s = String(n);
for (let i = 0; i < s.length; i++) { /* ... */ }
```

## 新しいインターフェース、古い実装

**使う場面:** これから呼びたい関数の形（名前、引数、戻り値）が、今ある関数と合っていないとき。

**手順:** 呼びたい形の関数を新しく作り、中身は古い関数を呼ぶだけにします。呼び出し元の
移行は、別のコミット（または別の作業）で行います。

```typescript
// 新しいインターフェース。中身は既存の calcTotal を呼ぶだけ
export function totalFor(items: Item[], options: { member: boolean; coupon?: string }): number {
  return calcTotal({ items, ...options });
}
```

## 読む順に並べる

**使う場面:** ファイルを上から読むと、使われる側の細部が先に来て、全体像が後に来るとき。

**手順:** 読み手が最初に知りたいもの（公開している関数、主な処理）を上に、細部を下に移します。
関数の中身は変えません。移動だけのコミットにします。

## 凝集の順に並べる

**使う場面:** 一緒に変更される関数や定義が、ファイルの中で離れているとき。

**手順:** 一緒に変わるものを隣に移します。移動だけのコミットにします。ファイルをまたぐ移動は
差分が大きくなりやすいので、1 回に 1 つのまとまりだけを動かします。

## 宣言と初期化を近づける

**使う場面:** 関数の先頭で変数をまとめて宣言し、ずっと後で値を入れているとき。

**手順:** 宣言を、最初に値を入れる場所の直前まで下げます。途中でその変数を読んでいる箇所が
ないことを確かめます。宣言と初期化を 1 行にまとめるのは、代入が 1 回だけの変数に限ります。
ループの書き方などは変えません。

```typescript
// 前
let count = 0;
// ... 10 行 ...
for (const it of order.items) count += it.qty;

// 後: 宣言をループの直前に下げただけ。ループは変えない
// ... 10 行 ...
let count = 0;
for (const it of order.items) count += it.qty;
```

## 説明用の変数・定数

**使う場面:** 長い式や、意味の分からない数値・文字列リテラル（`5000`、`0.9`、`"SAVE500"`）があるとき。

**手順:** 式の一部を、意味を表す名前の変数に取り出します。リテラルは名前付きの定数にします。
値と計算の順序は変えません（浮動小数点の結果が変わるのを避けるため）。名前は、そのコードの
業務上の意味がコードやテストから読み取れる場合にだけ付けます。読み取れなければ候補から外し、
報告に回します。

```typescript
const MEMBER_DISCOUNT_THRESHOLD = 5000;
const MEMBER_DISCOUNT_RATE = 0.9;

if (order.member && total > MEMBER_DISCOUNT_THRESHOLD) total *= MEMBER_DISCOUNT_RATE;
```

## 明示的な引数

**使う場面:** 関数が、グローバル変数・設定オブジェクト・大きな引数の一部などを暗黙に読んでいるとき。

**手順:** 関数が実際に使っている値だけを引数で受け取るようにし、呼び出し元で渡します。
すべての呼び出し元を同じコミットで更新します。export している関数（公開 API）では、パッケージの
外の呼び出し元を更新できないので、シグネチャを変えずに「新しいインターフェース、古い実装」で
新しい関数を足します。

## 文のまとまり

**使う場面:** 長い関数で、意味の違う処理が区切りなく続いているとき。

**手順:** 意味のまとまりごとに空行を入れます。最も小さく、最も安全な整理です。次の
「ヘルパーの抽出」の準備になることがよくあります。

## ヘルパーの抽出

**使う場面:** 関数の一部に、名前を付けられるはっきりした目的がある（小計の計算など）とき。

**手順:** その部分を関数に取り出し、元の場所から呼びます。引数と戻り値で受け渡しし、
取り出した関数の中から外側の変数を書き換えないようにします。**取り出すコードは書き換えずに
そのまま移します。** ループの形や変数の宣言を変えたくなったら、それは「対称性をそろえる」などの
別のパターンなので、抽出の前か後の別のコミットにします。

```typescript
// 元の calcTotal にあったループを、書き方を変えずにそのまま移す
function subtotal(order: Order): number {
  let total = 0;
  for (let i = 0; i < order.items.length; i++) {
    const it = order.items[i];
    total = total + it.price * it.qty;
  }
  return total;
}
```

## いったん 1 か所にまとめる

**使う場面:** 小さな関数やファイルに細かく分かれすぎていて、処理の流れを追うのに何か所も
飛ばなければならないとき。

**手順:** 関係する部分を一度 1 か所にインライン化して読みやすくします。全体が見えたら、
改めて「ヘルパーの抽出」などで分け直します（分け直しは別のコミット）。

## 説明用のコメント

**使う場面:** コードを読んでも分からない理由（なぜこの順序なのか、なぜこの例外があるのか）を、
読み手が知る必要があるとき。

**手順:** 「何をしているか」ではなく「なぜそうしているか」を書きます。コメントだけの
コミットにします。

## 冗長なコメントの削除

**使う場面:** コメントがコードと同じことを言っている（`// i を 1 増やす`）とき。

**手順:** 消します。**コメントとコードが食い違っている場合は、このパターンを使いません。**
どちらが正しいかは振る舞いの判断なので、整理の対象から外して報告します。
